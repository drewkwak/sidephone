**Category**

> Developer Tools

**Language**

> English

**Description**

```
See the mobile version of your page while you build the desktop one.

Sidephone puts a phone in Chrome's side panel and keeps it on the same page as your tab. Change a style, save, and both layouts update. A change that breaks the mobile layout shows up the moment you make it, without opening DevTools or switching views.

It works on localhost as soon as it is installed. Every other site stays off until you turn it on.

WHAT YOU GET

• A live phone-sized copy of your page that follows your tab as you navigate and reload
• Real responsive behavior: media queries, matchMedia and JavaScript-measured layouts respond to the device's width
• The same device list as Chrome DevTools: iPhone, Pixel, Galaxy, foldables, iPad, Surface and more
• A device frame with rounded corners, camera cutout, status bar and browser bars, so you see how much room your page really has
• An on-screen keyboard that appears when you focus a text field, to show what it would cover
• Scroll sync, so the mobile view follows the desktop one
• Pin, to hold the mobile view on one page while you browse elsewhere
• Rotate, and pop out into a window at the device's exact size
• Real size mode, calibrated to your monitor
• Light and dark themes

HOW SITE ACCESS WORKS

Sidephone has access to localhost and 127.0.0.1 only. To mirror another site, click the toolbar icon while you are on it and approve Chrome's prompt for that one site. You can switch a site off again in the view options.

PRIVACY

Sidephone collects nothing. No analytics, no accounts, no network requests of its own. Your settings stay in your browser.

GOOD TO KNOW

• The side panel holds a second copy of the page. You stay logged in, but text typed into a form in your tab does not appear in the mirror.
• It shows your layout at a device's width. It does not emulate touch input or the mobile user agent; use DevTools' device mode or a real phone for those.
• A few sites cannot be shown inside another page. For those, Sidephone can open the page in a phone-sized window instead.

Open source under the MIT license.
```

## Privacy tab

**Single purpose**

> Sidephone shows the page in the user's current tab at a mobile device's size in the side panel, so developers can check the mobile and desktop layouts of their site at the same time.

**Permission justifications**

sidePanel

> The extension's entire interface is a side panel that shows the mobile-size preview of the current tab.

activeTab

> When the user clicks the toolbar icon, the extension needs to know which site the current tab is on so it can ask for access to that one site. activeTab provides this for the clicked tab only, which lets the extension avoid requesting the "tabs" permission or broad host access.

scripting

> Used to register the extension's content script for sites the user has individually granted, and to inject it into tabs of those sites that were already open. The script reports the tab's scroll position to the side panel so the preview can scroll with it. Only the script file shipped in the package is injected.

declarativeNetRequestWithHostAccess

> Most websites send X-Frame-Options or a Content-Security-Policy frame-ancestors directive, which would prevent the preview from loading. While a preview is open, the extension uses session rules to remove those two response headers, only from documents loaded into the preview's own frame and only on sites the user has granted. Documents in normal tabs are never modified. The rules are removed when the preview closes.

Host permission: localhost and 127.0.0.1

> The extension is a tool for local web development. Access to local development servers lets it work immediately on the user's own projects: it reads the active tab's URL to load the same page in the preview, runs its content script there, and applies the header rules described above.

Host permission: optional access to other sites

> Not granted at install. If the user wants to preview a site other than localhost, the extension requests access to that single site with chrome.permissions.request, in response to the user's click. The user can revoke it from the extension's options or from Chrome's settings.

**Are you using remote code?**

> No. All code is included in the package. Nothing is fetched or evaluated at run time.

## Test instructions tab

```
No account or login is needed.

1. Open any website, for example https://example.com.
2. Click the Sidephone icon in the toolbar. The side panel opens and Chrome asks
   whether to allow Sidephone on this site. Choose Allow.
3. The side panel shows the same page inside a phone. Navigate in the tab; the
   phone follows.
4. Use the device menu (top left of the panel) to change device, and the icons
   at the top right to rotate, pin, pop out, and open the view options.

On http://localhost pages step 2 shows no prompt, because localhost access is
part of the install.
```
